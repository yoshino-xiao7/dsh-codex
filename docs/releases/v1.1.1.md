## 中文

### 变更

- 精确识别 pi-ai 在 Codex 服务过载时返回的固定错误文案，并将其归一化为可有限重试的服务端错误；普通的 busy/overloaded 文本不会被误判。
- 服务过载发生在安全文本输出之后时，保留已有输出并引导用户手动发送“继续”。工具调用已经开始时仍禁止整次请求重放，避免重复输出或工具副作用。
- 用户界面只显示脱敏的中英双语服务繁忙提示，不透传原始服务端错误。

### 兼容性

- 精确兼容目标仍为 DeepSeek Harness `0.1.1-rc.2`、pi-ai `0.82.1` 与 Node.js `>=22.19.0 <25`。
- 本次修复只改变已知 Codex 服务过载错误的分类与流恢复行为，不改变 OAuth、模型目录、额度读取、传输选择、Fast 或请求参数合同。
- 完整检查与 Linux、macOS、Windows CI/profile smoke 已绑定本版本候选并由维护者批准；正式工作流继续校验同一来源、供应链证据、Registry 与 GitHub Release。发布后真实账号验证从独立的 `1.1.1` 记录以 `0/13` 开始，不继承旧版本结论。

## English

### Changes

- Precisely recognize the fixed pi-ai Codex overload message and normalize it as a bounded-retry server failure without misclassifying ordinary busy or overloaded prose.
- Preserve safe text already emitted before an overload and direct the user to send “continue” manually. Full-request replay remains disabled after a tool call has started, preventing duplicate output or tool side effects.
- Show only a sanitized bilingual service-overload message instead of exposing the raw server error.

### Compatibility

- The exact targets remain DeepSeek Harness `0.1.1-rc.2`, pi-ai `0.82.1`, and Node.js `>=22.19.0 <25`.
- This fix changes only classification and stream recovery for the known Codex overload failure. It does not change OAuth, the model catalog, usage reads, transport selection, Fast, or the request-parameter contract.
- Full checks and Linux, macOS, and Windows CI/profile smoke are bound to this release candidate and approved by the maintainer. The protected workflow continues to verify the same source, supply-chain evidence, the Registry, and the GitHub Release. Post-release live-account validation starts at `0/13` in a fresh `1.1.1` record and inherits no conclusion from an older release.
