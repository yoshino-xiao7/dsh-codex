## 中文

### 变更

- 更新 Cordis `4.0.2`、Schemastery `3.18.2`、pi-ai `0.84.4` 与 TypeScript `7.0.2`，并显式固定 Harness 运行时所需的 include、loader 与原生模块加载依赖。
- 启用严格 peer dependency 安装检查，让不兼容的运行时组合在构建与 CI 阶段直接失败。
- 发布候选的 npm 漏洞审计现在会对 429、5xx、DNS 与网络超时执行最多五次的有界重试，单次最多等待 60 秒并采用最长 60 秒的退避；真实漏洞立即失败，重试耗尽后仍失败关闭。

### 兼容性

- 精确兼容目标为 DeepSeek Harness `0.1.1-rc.2`、pi-ai `0.84.4` 与 Node.js `>=22.19.0 <25`。
- 本版本不改变 OAuth、模型目录、额度读取、传输选择、Fast、请求参数合同或已有故障恢复语义。
- 完整检查与 Linux、macOS、Windows CI/profile smoke 已绑定本版本候选并由维护者批准；正式工作流继续校验同一来源、供应链证据、Registry 与 GitHub Release。发布后真实账号验证从独立的 `1.1.2` 记录以 `0/13` 开始，不继承旧版本结论。

## English

### Changes

- Update Cordis `4.0.2`, Schemastery `3.18.2`, pi-ai `0.84.4`, and TypeScript `7.0.2`, while explicitly pinning the include, loader, and native-module loading dependencies required by the Harness runtime.
- Enable strict peer-dependency installation checks so incompatible runtime combinations fail during build and CI.
- Add at most five bounded retries for npm audit 429, 5xx, DNS, and network-timeout failures when building a release candidate, with a 60-second per-attempt limit and backoff capped at 60 seconds. Real vulnerabilities fail immediately, and exhausted retries remain fail-closed.

### Compatibility

- The exact targets are DeepSeek Harness `0.1.1-rc.2`, pi-ai `0.84.4`, and Node.js `>=22.19.0 <25`.
- This release does not change OAuth, the model catalog, usage reads, transport selection, Fast, the request-parameter contract, or existing recovery semantics.
- Full checks and Linux, macOS, and Windows CI/profile smoke are bound to this release candidate and approved by the maintainer. The protected workflow continues to verify the same source, supply-chain evidence, the Registry, and the GitHub Release. Post-release live-account validation starts at `0/13` in a fresh `1.1.2` record and inherits no conclusion from an older release.

### Acceptance record

- [`v1.1.2.acceptance.json`](v1.1.2.acceptance.json) is the independent acceptance record for this version and is bound to the candidate commit, three-platform evidence, and maintainer approval. Post-release live-account validation continues from `0/13`.

### Artifact verification

- SHA-256: generated by the protected release workflow and attached to the GitHub Release.
- SRI: generated by the protected release workflow, read back from the Registry, and attached to the GitHub Release.
