## 中文

### 变更

- 新增 Fast、Transport、回复详略和推理摘要的持久化全局默认值；会话只保存用户明确修改的稀疏覆盖，`/codex reset` 恢复当前全局默认值。
- 新增应用运行期间的低额度、耗尽与重置提醒；提醒只依据已验证的 Codex 5 小时和每周窗口，剩余不高于 20% 时显示。
- 每周额度的相对天数会在页面停留期间按本地显示边界自动递减；只有真实 reset 节点才读取账号额度，不新增轮询或 usage RPC。
- 修改全局 Transport 默认值时，只让继承该默认值的会话切换到新的连接 generation；显式覆盖会话与正在进行的请求保持不变，旧连接会在在途请求结束后清理。
- 新增需用户二次确认的一次性真实网络诊断。同意框显示经白名单字符与长度校验的实际模型 ID，执行时使用同一模型；请求会消耗账号额度，固定使用 SSE、关闭 Fast、只携带一条短提示，不携带会话历史或工具，也不自动重试。请求遵循 Codex SDK 的公开 wire schema，不注入私有输出上限；专用端点没有可用的服务端硬输出上限，插件会在首次可见文本后立即结束流，但取消或结束流不能保证未消耗额度。
- 新增最多 20 条的进程内脱敏诊断历史，支持显式加载、清空和导出经固定 schema 验证的 JSON。

### 安全与隐私

- 额度提醒不启动后台轮询、循环重试或操作系统通知；到达已验证的重置节点时只刷新一次。
- 真实诊断的同意凭据短期且仅可使用一次；过期或已使用后不能重放。前置检查有 30 秒 deadline，内部超时不会冒充用户取消，也不会进入模型请求 probe。请求开始后取消不能保证未消耗额度，最终脱敏结果会按“已尝试”保留；进程级隔离只在旧 `next()` 收敛、`return()` 成功返回 `{ done: true }` 且临时状态清理成功后放行，无法确认时需重启进程。
- 诊断报告与导出不包含 token、account ID、请求 ID、提示、模型输出、原始响应或原始错误。历史不写入配置或磁盘，进程重启后清空。

### 兼容性

- 精确兼容目标仍为 DeepSeek Harness `0.1.1-rc.2`、pi-ai `0.82.1` 与 Node.js `>=22.19.0 <25`。
- 完整检查与 Linux、macOS、Windows CI/profile smoke 已绑定本版本候选并由维护者批准；正式工作流继续校验同一来源、供应链证据、Registry 与 GitHub Release。发布后真实账号验证从独立的 `1.1.0` 记录以 `0/13` 开始，不继承旧版本证据。
- 单次真实网络诊断只使用页面列出的模型验证一次 SSE 短文本请求；它没有服务端硬输出上限，只在首次可见文本后尽快结束流，不替代 OAuth、图片、工具、replay、Fast 或全部 Transport 的发布验收。

## English

### Changes

- Added persistent global defaults for Fast, Transport, reply verbosity, and reasoning summary. Conversations retain only fields the user explicitly overrides, and `/codex reset` restores the current global defaults.
- Added low-usage, exhausted-window, and reset reminders while the app is running. Reminders use only verified Codex five-hour and weekly windows and appear at 20% remaining or below.
- Weekly relative-day labels now decrement at local display boundaries while the page remains open. Only the actual reset boundary reads account usage, adding neither polling nor usage RPCs.
- Changing the global Transport default moves only inheriting conversations to a new connection generation. Explicitly overridden conversations and in-flight requests remain unchanged, and old connections are cleaned after their active requests drain.
- Added a one-shot real-network diagnostic behind an explicit second confirmation. The consent displays the actual model ID after character-allowlist and length validation, and execution uses that same model. It consumes account usage, forces SSE with Fast off, and carries one short prompt with no conversation history, tools, or automatic retry. The request follows the public Codex SDK wire schema and injects no private output cap. The dedicated endpoint exposes no usable server-side hard output limit; the plugin tears down after the first visible text, but cancellation or teardown cannot guarantee that no usage was consumed.
- Added at most 20 sanitized diagnostic reports in process memory, with explicit loading, clearing, and export of fixed-schema-validated JSON.

### Security and privacy

- Usage reminders start no background polling, retry loop, or operating-system notification. Reaching a verified reset boundary triggers exactly one refresh.
- Real-diagnostic consent is short-lived and single-use. Expiry or prior consumption cannot replay it. Preflight has a 30-second deadline; internal timeout is distinct from user cancellation and never enters the model-request probe. Cancellation after dispatch cannot guarantee that usage was not consumed, so the final sanitized result remains marked as attempted. Process-wide quarantine releases only after the old `next()` settles, `return()` successfully yields `{ done: true }`, and temporary-state cleanup succeeds; otherwise process restart is required.
- Reports and exports contain no tokens, account IDs, request IDs, prompts, model output, raw responses, or raw errors. History is written to neither configuration nor disk and disappears at restart.

### Compatibility

- The exact targets remain DeepSeek Harness `0.1.1-rc.2`, pi-ai `0.82.1`, and Node.js `>=22.19.0 <25`.
- Full checks and Linux, macOS, and Windows CI/profile smoke are bound to this release candidate and approved by the maintainer. The protected workflow continues to verify the same source, supply-chain evidence, the Registry, and the GitHub Release. Post-release live-account validation starts at `0/13` in a fresh `1.1.0` record and does not inherit evidence from an older release.
- The one-shot real-network diagnostic uses the model listed in the UI to verify only one short SSE text request. It has no server-side hard output limit and merely tears down after the first visible text, so it does not replace release acceptance for OAuth, images, tools, replay, Fast, or every Transport.
