## 中文

### 变更

- 修复在 DeepSeek Harness `0.1.2-rc.1` Web profile 中因导入已移除的 `installSettingsSection` / `settingsNamespace` 而无法到达 Runtime ready 的问题。
- 改用 `ctx.settings.installSection(ctx, "dsh-codex", Config, entry, hooks)` 注册插件设置命名空间，namespace 使用合法字符串常量 `"dsh-codex"`。
- 发布包门禁扫描全部 `dist/**`，避免只检查顶层 entry 而遗漏 internal chunk。
- 将 Web client inject 从已停止发布的 `dsh-client-runtime` 切换为 `dsh-client-ui-renderer`，并把 Harness/settings peer 精确固定到 `0.1.2-rc.1`。
- 本版本不再声明兼容 DeepSeek Harness `0.1.1-rc.2`。

### 兼容性

- 精确兼容目标为 DeepSeek Harness `0.1.2-rc.1`、pi-ai `0.84.4` 与 Node.js `>=22.19.0 <25`。
- 本版本不改变 OAuth、模型目录、额度读取、传输选择、Fast、请求参数合同或已有故障恢复语义。
- 完整检查与 Linux、macOS、Windows CI/profile smoke 必须绑定本版本候选并由维护者批准后才能正式发布；发布后真实账号验证从独立的 `1.2.0` 记录以 `0/13` 开始，不继承旧版本结论。

### 验收记录

- [`v1.2.0.acceptance.json`](v1.2.0.acceptance.json) 是本版本独立验收记录；当前为草稿，发布前绑定候选提交、三平台证据与维护者批准。发布后真实账号验证从 `0/13` 继续记录。

## English

### Changes

- Fix the Runtime failing to reach ready on DeepSeek Harness `0.1.2-rc.1` Web profiles because the plugin imported the removed `installSettingsSection` / `settingsNamespace` named exports.
- Register the plugin settings namespace with `ctx.settings.installSection(ctx, "dsh-codex", Config, entry, hooks)`, using the legal string constant `"dsh-codex"`.
- Scan every packed `dist/**` file in the publication gate so a leftover API in an internal chunk cannot escape a top-level entry check.
- Switch the Web client inject list from the unpublished `dsh-client-runtime` package to `dsh-client-ui-renderer`, and pin Harness/settings peers exactly to `0.1.2-rc.1`.
- This release no longer claims compatibility with DeepSeek Harness `0.1.1-rc.2`.

### Compatibility

- The exact targets are DeepSeek Harness `0.1.2-rc.1`, pi-ai `0.84.4`, and Node.js `>=22.19.0 <25`.
- This release does not change OAuth, the model catalog, usage reads, transport selection, Fast, the request-parameter contract, or existing recovery semantics.
- Full checks and Linux, macOS, and Windows CI/profile smoke must be bound to this release candidate and approved by the maintainer before publication. Post-release live-account validation starts at `0/13` in a fresh `1.2.0` record and inherits no conclusion from an older release.

### Acceptance record

- [`v1.2.0.acceptance.json`](v1.2.0.acceptance.json) is the independent acceptance record for this version. It is currently a draft; the candidate commit, three-platform evidence, and maintainer approval are recorded before publication. Post-release live-account validation continues from `0/13`.

### Artifact verification

- SHA-256: generated by the protected release workflow and attached to the GitHub Release.
- SRI: generated by the protected release workflow, read back from the Registry, and attached to the GitHub Release.
